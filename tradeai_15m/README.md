# TradeAI: исследовательская версия для 15 минут

Это исходный Telegram-бот пользователя, доработанный под 15-минутные свечи Bybit USDT perpetual. По умолчанию он получает данные Testnet, показывает сигналы и **не отправляет ордера**. Технические тесты не подтверждают, что торговля через Bybit будет работать во всех условиях.

## Главное о результате

Из 16 заранее заданных вариантов на первых 70% загруженной истории был выбран пробой 96-свечного диапазона с ATR-стопом 2 и целью 2R. Он оказался наиболее сильным **по выбранному критерию на этой обучающей выборке**, но и он не продемонстрировал устойчивой прибыльности: на исследовательском позднем участке симуляция убыточна по каждой из четырёх монет. Это не «самая прибыльная стратегия» и не подтверждение её применимости на реальных деньгах. Результаты и ограничения — в [BACKTEST_RESULTS_RU.md](BACKTEST_RESULTS_RU.md), все варианты — в `candidate_trials.csv`.

Поздний участок не является полностью независимым: результат первого варианта на нём был просмотрен до расширения поиска. Перед любыми дальнейшими выводами необходимы новые, ещё не использованные данные, более длинный период, учёт funding и проверка на Testnet. До этого не включайте торговлю реальными средствами.

## Как формируется сигнал

* Анализируются только завершённые свечи **15 минут** для SOLUSDT, XRPUSDT, DOGEUSDT и ADAUSDT.
* LONG: цена закрытия выше максимума high **предыдущих 96 свечей**. SHORT: цена закрытия ниже минимума low предыдущих 96 свечей. Текущая свеча не входит в диапазон.
* Ориентир входа — цена закрытия сигнальной свечи. Стоп отстоит на **2 × ATR(14)**, цель — на **2 размера стопа (2R)**. Реальная цена входа и соотношение риск/прибыль могут быть иными.
* Бот запрашивает последние 250 свечей и исключает формирующуюся; отвергает устаревшие данные, пропуски и ошибочные значения. EMA и RSI могут отображаться как диагностические значения, но они **не являются фильтрами входа**.
* Сканирование по умолчанию каждые 300 секунд, а не в момент закрытия свечи. Сигнал по той же свече не открывается повторно после зафиксированной сделки.

## Важные пределы безопасности

* `TRADING_ENABLED=false` означает режим сигналов, **не** полноценный paper trading: виртуальный баланс и сделки в этом режиме не ведутся.
* `BYBIT_TESTNET=true` выбирает и рыночные данные, и подключение к бирже Testnet. `TRADING_ENABLED=true` включает отправку ордеров в выбранную среду. Для mainnet дополнительно требуется `ALLOW_MAINNET_TRADING=true`; не включайте его на основании этого теста.
* Размер позиции рассчитывается от вручную заданного `RISK_BALANCE_USDT`, а не от автоматически считанного баланса Bybit. По умолчанию плановый риск на сделку — до 0,5%, есть буферы и ограничение номинала. Это **не гарантия максимального убытка**: возможны гэпы, исполнение по худшей цене, комиссии, funding и ликвидация. Минимальный объём биржи не увеличивается — сделка пропускается. При балансе 12 USDT много сделок могут не проходить минимум биржи.
* Локальный лимит — одна открытая или ещё не сверенная сделка среди монет бота. Используйте отдельный аккаунт/субаккаунт без ручных позиций и иных ботов. Внешние клиенты, размещающие ордера одновременно, не блокируются локальным замком.
* Для управления защитой нужен one-way position mode (`positionIdx=0`). Защитные TP/SL передаются вместе с входом. Подтверждение исполнения и защиты требует сверки; при неизвестном результате новые входы блокируются сохраняемым флагом. Сетевое поведение Bybit, частичные исполнения и сочетание параметров этого API **не проверены реальными сделками даже на Testnet**.
* Для сохранения SQLite и предохранителя нужен постоянный общий том `/app/data`; запускайте только один экземпляр. Блокировка процесса защищает только экземпляры с одним общим томом. Не используйте отдельные тома для нескольких копий.
* История закрытого PnL сопоставляется по символу, стороне и времени, а не строго по уникальному ID каждой сделки. Она может быть неполной или неоднозначной, особенно если аккаунт используется вручную. Неподтверждённое закрытие остаётся открытым в БД и блокирует новые входы.
* Стоп-лосс не защищает от всех потерь. Тест по свечам не моделирует ликвидацию, funding, стакан, частичные исполнения и все задержки.

## Railway: безопасное обновление

1. **До замены файлов** установите в Railway `TRADING_ENABLED=false` и дождитесь применения. Если ключ или токен когда-либо попадал в чат, снимок экрана или репозиторий, отзовите его и выпустите новый. Не добавляйте секреты в ZIP или Git.
2. Сохраните резервную копию проекта и постоянного тома. Замените файлы на содержимое архива, установите Python-зависимости и разверните приложение. В проекте теперь есть распознаваемый `Dockerfile`; если в Railway уже настроен другой способ сборки или команда запуска, проверьте настройки проекта.
3. Подключите один постоянный Volume к `/app/data`. Значения Railway Variables:

   ```text
   TELEGRAM_TOKEN=<токен Telegram>
   TELEGRAM_ADMIN_CHAT_ID=<ваш числовой chat ID>
   BYBIT_API_KEY=<ключ Bybit Testnet; в режиме сигналов необязательно>
   BYBIT_API_SECRET=<секрет Bybit Testnet; в режиме сигналов необязательно>
   BYBIT_TESTNET=true
   TRADING_ENABLED=false
   ALLOW_MAINNET_TRADING=false
   BYBIT_LEVERAGE=3
   RISK_BALANCE_USDT=12
   RISK_PER_TRADE_PCT=0.5
   MAX_ENTRY_DEVIATION_PCT=0.2
   RAILWAY_VOLUME_MOUNT_PATH=/app/data
   TRACKER_INTERVAL_SECONDS=300
   SCAN_INTERVAL_SECONDS=300
   ```

   Значения в `<...>` замените своими, если они нужны. Все булевы значения задавайте строго как `true` или `false`; опечатка блокирует новые ордера. Пример конфигурации — `.env.example`.
4. Отправьте боту `/myid` и впишите полученный числовой ID в `TELEGRAM_ADMIN_CHAT_ID`, затем перезапустите сервис. Откройте `/start` → «Статус бота»: ожидаются Testnet и отключённая торговля. Пока ID не задан, остальные команды защищены.
5. При необходимости проверьте получение сигналов с `TRADING_ENABLED=false`. Тестнет-ордера не проверялись при создании этой сборки; перед их самостоятельным включением изучите поведение с отдельным Testnet-счётом и убедитесь, что данные и ордера идут именно в Testnet. Включение `TRADING_ENABLED=true` разрешит автоматические Testnet-ордера, а не просто уведомления.

## Если сработал предохранитель

Бот выводит предупреждение и сохраняет флаг `bybit_new_orders_block.json` в Volume. **Не удаляйте файл и не перезапускайте торговлю автоматически.** Остановите сервис, проверьте в нужной среде Bybit фактические позиции, активные ордера, исполнения, TP/SL и историю, а также запись в SQLite. Требуется вручную устранить несоответствие и убедиться, что риска незарегистрированной позиции нет. Только после полной проверки владелец может решить удалить флаг на постоянном томе и снова запустить сервис. Если флаг не удалось записать на диск, немедленно отключите торговлю: сохранение блокировки после перезапуска не гарантировано. Не показывайте ключи специалистам и в скриншотах.

## Локальный запуск на Linux / WSL

Требуются Python 3.12 и каталог для данных с правом записи. Нативный Windows здесь не проверялся: модуль безопасности использует `fcntl`.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполните Telegram-настройки в .env, установите безопасные флаги.
mkdir -p data
# В .env задайте RAILWAY_VOLUME_MOUNT_PATH=/абсолютный/путь/к/data
python bot.py
```

Команда тестов: `python -m unittest discover -s tests -v`. Тесты используют заглушки биржи и не выставляют реальные ордера. В меню «Бэктест 15м» используется до 1000 последних закрытых свечей выбранной среды; это короткий приблизительный тест, не достаточный для выбора стратегии.

## Повтор исследования

`historical_data/` содержит публичные исторические свечи Bybit mainnet и `manifest.json` с датами. `python research_backtest.py` воспроизводит отчёт для текущей стратегии. `python research_candidates.py` воспроизводит сравнение вариантов. `python download_history.py --days 90` получает новую историю из публичного API без ключей, но результаты изменятся. У сценария и реальной торговли разная модель размеров, округления и портфельных ограничений; реальные результаты могут существенно отличаться.
